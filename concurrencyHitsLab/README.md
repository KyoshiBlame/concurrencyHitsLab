# concurrencyHitsLab
Лабораторная на тему параллельное программирование

Программа моделирует диспетчерскую систему с центральным накопителем заявок.

## Что реализовано

- Генератор заявок в отдельной горутине.
- Центральный диспетчер, который единственный изменяет накопитель заявок.
- Центральный накопитель ограниченной ёмкости.
- Если накопитель заполнен, диспетчер временно не читает канал генератора, поэтому генератор блокируется на отправке и «засыпает».
- Отдельный управляющий поток `GroupManager` для каждой группы оборудования.
- Promise/future-аналог через `WorkRequest` и `Reply chan bid.Bid`.
- Приоритеты заявок: `3` → `2` → `1`; внутри одного приоритета сохраняется FIFO.
- Каждое устройство работает в отдельной горутине.
- Семафор на каждую группу ограничивает количество одновременно работающих устройств до 80%.
- Вывод состояния устройств, группы, приоритета, оставшегося времени, размера накопителя и активных устройств.
- Корректная остановка через `context.Context` и `sync.WaitGroup`.

## Запуск

```bash
go run ./cmd
```

Введите:

1. ёмкость центрального накопителя;
2. количество групп `n`, где `n > 2`;
3. количество устройств в группе `m`, где `m > 3`.

Для завершения нажмите `Enter` или `Ctrl+C`.
